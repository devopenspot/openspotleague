# Share image (OG) card sheet

A local, never-deployed page with one 1200×630 card per static share image. It lives outside `src/` and `public/`, so the app does not build, serve or lint it. Open `index.html` directly in a browser.

Full guide (shipping a card, scaling, generated images): [`docs/og-cards.md`](../../docs/og-cards.md).

Images in `assets/` are copies from `public/`. Brand colours are copied by hand from `DESIGN.md` / `src/app/globals.css`.

## Exporting the PNGs

Fastest: run the export script. It serves this folder locally and renders every card to an exact 1200×630 PNG in `design/og-cards/out/` (git-ignored) with headless Chrome:

```bash
design/og-cards/export.sh
```

Single card in the browser: `index.html?only=<id>` (for example `?only=league`) shows just that card at 0,0.

## Taking screenshots by hand (Chrome)

1. Open `design/og-cards/index.html`. Make sure the safe-zone checkbox is off.
2. Open DevTools and select the `<section class="og" id="…">` element of a card.
3. Press Cmd+Shift+P, then run **Capture node screenshot**.
   - At normal zoom on a Retina screen this gives 2400×1260 (fine for crawlers). For exactly 1200×630, first turn on the device toolbar with DPR 1, or downscale afterwards with `sips -z 630 1200 file.png`.
4. Save the screenshot under the filename below.

## Cards

| id | file | used for |
| --- | --- | --- |
| `default` | `og-default.png` | every page without its own image |
| `tv` | `og-tv.png` | `/tv` landing (videos keep their own thumbnails) |
| `league` | `og-league.png` | `/league` landing |
| `games-training` | `og-games-training.png` | training games |
| `games-battle` | `og-games-battle.png` | battle (challenge) games |
| `league-results` | `og-league-results.png` | contest ended / results published |
| `games-results` | `og-games-results.png` | game ended |
| `rider` | `og-rider.png` | rider profile (generic) |
| `curator` | `og-data-curator.png` | `/support/data-curator` invitation |

Spot images, TV video thumbnails, contest covers and per-rider result cards are generated by the app and are not part of this sheet.

Wiring these files into page metadata is a separate step.
