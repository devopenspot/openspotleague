# Repository Guide

Single private Next.js 16 App Router app ("OpenSpot" — map of sports spots, events, league games, TV). Node 22 (`.nvmrc`), pnpm 10 pinned via `packageManager`. `pnpm-workspace.yaml` sets only pnpm settings (`verifyDepsBeforeRun`, `minimumReleaseAge`, `allowBuilds`) — not a monorepo. No CI workflows in-repo; local checks are the gate.

## Verification

- `pnpm lint` → `eslint src` only. `pnpm typecheck` → `tsc --noEmit` (strict, `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`). `pnpm test` → `vitest run`; single file: `pnpm test src/path/file.test.ts`.
- Vitest only picks up `src/**/*.{test,spec}.{ts,tsx}`, runs in `happy-dom` with `globals: true`, and stubs `server-only` (via `vitest.server-only.ts`) plus `@` → `./src/*`.
- `pnpm build` is DB-free: layouts call `connection()` and wrap DB reads in `withSafeDefault`/`withSafeDefaultResult` (`src/lib/utils/safe-fetch.ts`) so missing DB/Supabase env renders empty fallbacks instead of 500s. Do not add a DB requirement to the build.

## Architecture

- `src/proxy.ts` is the Next.js 16 proxy (not `middleware.ts`): Supabase session refresh, security headers (TV routes get `frame-ancestors *`), and tiered per-IP rate limiting (in-memory; bypassed when `NODE_ENV=test`). League/games API routes add route-local limiters on top (`src/app/api/{games,league}/rate-limit.ts`) — reuse them for new endpoints there.
- Call flow: pages/route handlers → `src/lib/services/*` → `src/lib/repositories/*` (interfaces) → Drizzle implementations. Services at several levels import `drizzle-orm` directly — the hard rule is never import Drizzle from pages or route handlers.
- Challenge games and league events each split a pure, unit-tested domain engine (`src/lib/games/*`, `src/lib/league/*` — state machines, scoring, capability math; no DB/IO) from service orchestration (`src/lib/services/{games,league}/*`), which is the only writer: every mutation runs `withDbWrite` + `db.transaction` + `expectedVersion` OCC + a `requestFingerprint` for idempotent replay. Keep new domain rules in the engine (testable), orchestration in services.
- Every repository method is wrapped in a Proxy (`src/lib/repositories/index.ts`) applying `withDbRetry`: 15s deadline, 3 attempts on transient connection errors for reads; writes run in `db.transaction` with retry disabled.
- Mutations must not call `revalidateTag` inside a transaction — `withDbWrite` (`src/lib/db/client.ts`) flushes a deferred invalidation queue after commit (`src/lib/cache/deferred.ts`; use `queueTagRevalidate`). Spot/event services share `revalidateSpotCaches`/`revalidateEventCaches` invalidation helpers — extend those, don't hand-roll tag lists.
- Admin content routes map errors via `mapMutationErrorResponse` (`src/lib/api/admin-handler.ts`): typed domain errors keep their message (400/409), not-found message prefixes → 404, upload validation → 400, timeout/connection → 503, everything else → 500 "Internal error" (never echo raw messages).
- Storage upload validation failures throw `UploadValidationError` (`src/lib/storage/errors.ts`) — routes check `instanceof`; don't string-match error messages.
- Spot/event deletes share the OCC + audit flow via `deleteWithOccAudit` (`src/lib/repositories/core/occ-delete.ts`); TV audit rows use `recordContentAudit` with `entityType: "tv_video"`. Spot deletes additionally detach games via `detachSpotDependents` (`src/lib/repositories/spot/spot-delete-plan.ts`, see its header comment for tier semantics) — any new `RESTRICT → spots` FK must be handled there; unhandled FK violations surface as 409 by design.
- Feature specs live in `.agents/specs/<feature>/*.spec.md` — `league/` (api/engine/ui/email/data-model/verification/plan/business-rule), `tricks/`, `spots-migration/`. Check the relevant spec before touching league, challenge-game, or catalog code; `sportEvents` schema comments also cross-link the league specs.
- Cache Components enabled (`cacheComponents: true` in `next.config.mjs`): cached services use `"use cache"` + `cacheTag` + `cacheLife`; mutations must call `revalidateTag(tag, cacheLifeProfile)` — Next 16 requires the exact profile object reference as second argument (inline literals don't match; reuse `src/lib/cache/lifetimes.ts` constants) — plus `revalidatePath` where relevant.
- Root and map layouts fan out reads via `Promise.all` + `withSafeDefault` so anonymous browsing renders when the DB is unreachable. Global DB concurrency gating lives inside `withDbRetry` (`withGlobalDbConcurrency`); don't add per-layout gating.
- Displayed spot weather is client-side only via `/api/weather`; per-spot `"use cache"` (`src/lib/weather/weather-cached.ts`) absorbs the calls. Do not restore an all-spots weather fetch to SSR/layouts.

## Database

- Runtime `getDatabaseUrl()` (`src/lib/config/env.ts`) resolves `SUPABASE_DATABASE_URL` (pooler `:6543`, Transaction mode, required on Vercel) before `SUPABASE_DIRECT_URL` (direct `:5432`, local DDL only). `drizzle.config.ts` uses a *different* order: `SUPABASE_DIRECT_URL` (preferred), `DB_CONNECTION_STRING`, `DATABASE_URL`; `DB_CONNETION_STRING` (typo) throws.
- Schema source is `src/db/schema.ts` (re-exports `src/db/schema/index.ts`); `pnpm exec drizzle-kit generate` writes SQL to `supabase/migrations`. Applying is done by the custom applier `pnpm db:apply` (`src/db/apply-sql.ts`: advisory-locked transaction, `schema_migrations` ledger, applies only pending files) — distinct from drizzle-kit `migrate`. `pnpm db:fresh` = reset + apply; `pnpm db:fresh:seed` adds seed. Drift hashes normalized statements (comment/format-insensitive); applied files are immutable — semantic fixes ship as new files, and legacy ledger hashes self-heal with a `↻` log line. Never edit an already-applied migration file.
- DB CLI scripts import `src/db/load-env.ts`, which loads `.env.local` with `override=true` before `.env` — `.env.local` wins even over exported shell vars. `.gitignore` excludes `.env*` (only `.env.example` is committed), so new env files must also be excluded. Trick catalogs refresh per discipline via `pnpm db:seed-tricks:<skateboard|bmx|scooter|roller>` (generic `pnpm db:seed-tricks <discipline>`, `src/db/seed-tricks.ts` → `seedChallengeCatalogForDiscipline` in `src/db/seed-data/challenge-catalogs.ts`): same replace + snapshot semantics as the full seed, so the JSON fixture is the source of truth and tricks missing from it are deleted.
- Never expose `SUPABASE_SECRET_KEY` (`sb_secret_...`); only privileged server modules may use it (`getAdminClient()` in `src/lib/auth/auth.ts`, `src/lib/supabase/admin.ts`). Browser-safe keys are `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. `ADMIN_EMAILS` is bootstrap-only; runtime authorization uses DB roles/permissions. Copy variable names from `.env.example`.

## UI conventions

- Form controls must render `16px` on mobile — iOS Safari auto-zooms focused inputs below that. Global guard in `src/app/globals.css` (`@media (max-width: 639px)` with `!important`); for new inputs prefer `text-base sm:text-sm`. Never "fix" zoom via viewport `maximum-scale`/`user-scalable=no`.
- Design language (see `DESIGN.md` + `DESIGN_MAP.md` + `docs/USER_STORIES.md` stack notes): monochrome system, Plus Jakarta Sans; `--color-primary` is `#0a0a0a` (black, reserved for CTAs/active/critical states), gradient `from #ea580c via #dc2626 to #b91c1c` hero/marketing only; `radius-lg` 16px or `full` for interactive controls; shell chrome (header, nav, drawer) shares a 64px height and shared margins — treat as one continuous piece. All maps (`LeafletCanvas`, `SpotStaticMap`, `SpotMapFallback`) use the dedicated high-contrast dark palette in `DESIGN_MAP.md` (`--color-map-*` tokens and `--map-tile-filter` on `.leaflet-tile-pane` / `.map-tile-dark`) strictly for the map canvas, tiles, and on-map markers/overlays; never apply `DESIGN_MAP.md` dark mode to the surrounding page or layout.
- Images stay `unoptimized: true` (`next.config.mjs`): sharp generates 128/400/800 WebP variants at upload (`src/lib/storage/index.ts` — R2 is the object plane via `STORAGE_PROVIDER=r2`; `src/lib/supabase/storage.ts` is a deprecated re-export shim). Don't enable Next image transforms.
- `src/components/games/create/GameCreateForm.tsx` was split: in-file helper components live in `form-parts.tsx` (same dir) — keep new form UI there; trick-catalog AND-logic (level/spotType/category filtering + counts) lives in `trick-catalog-filters.ts` with unit tests. `createGame`'s idempotency fingerprint (`fingerprintFor` in `src/lib/services/games/index.ts`) uses canonical sorted-keys JSON via `requestFingerprint` — key order is not load-bearing; legacy rows still match via `isFingerprintMatch`.
- `src/components/games/layout/Header.tsx` is split too: presentational blocks in `header-parts.tsx`, pure derived state via `deriveHeaderState` in `header-state.ts` (tested), localStorage helpers in `share-onboarding.ts`. Note: TS aliased-condition narrowing is lost across module boundaries — keep explicit `game &&` guards where JSX dereferences `game`.
- `src/lib/env.ts` and `src/hooks/useSpotWeather.ts` shims are deleted; import from `@/lib/config/env` and `@/hooks/data/useSpotWeather` (and the other `hooks/{data,map,preferences,ui}` subdirs) directly. `src/lib/safe-fetch.ts` still exists as a deprecated re-export shim — never add new imports of it; use `@/lib/utils/safe-fetch`.

## Security headers

- Security/CSP headers live in two places that must be kept in sync: `next.config.mjs` `headers()` (static/build-time responses; CSP string duplicated inline because TS isn't resolvable there) and `src/lib/security/headers.ts` (`securityHeaders` + `cspValue()`, applied at runtime by `src/proxy.ts` as `Content-Security-Policy-Report-Only`). Changing one without the other causes drift. TV routes additionally get `frame-ancestors *` from the proxy.
